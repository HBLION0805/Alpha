# Prospective options research protocol and decision references

Task OPT-RESEARCH-PROTOCOL-1. Design reviewed September 7, 2026; current configured
model, no delegation. Complexity medium/high. Work in bounded continuation units.

## Problem and reviewed scope

The sample auditor currently accepts a declared protocol reference/hash without
the underlying definition or a registration clock. The context capture now has
an actual post-payload-write receipt, but no decision uses that receipt. Existing
paper plans and research configurations are retrospective declarations. Attaching
new files cannot establish earlier feature knowledge for those cases.

Add independent protocol registration and subsequent research decision references.
Preserve all existing sample, paper, review, context and quote-study artifacts.
Do not alter the frozen opening collection or silently choose future datasets,
partition dates, model parameters or a profitable strategy.

## Protocol declaration and validation

The v1 declaration contains protocol/dataset IDs, SYNTHETIC_FIXTURE or
UNVERIFIED_IMPORT origin, strategy version, exact GLD/IBIT scope, the existing
TRAIN/VALIDATION/HOLDOUT windows and minimum elapsed-time gap, plus complete
bounded feature and outcome definition text with explicit reference IDs. These
texts are frozen declarations, not executable code, instructions to the agent,
verified feature lineage or an evaluated model. Reject empty/control-containing
text, unsafe identifiers, unknown keys and unsupported scope/authority fields.

Use the original sample auditor with zero samples to validate the window/gap
contract. Its expected empty-partition blockers remain in the output. Do not
duplicate the chronological window rules, imply there are any observations, or
convert successful protocol syntax validation into a ready sample dataset.

First bounded unit implements the typed declaration and pure assessment. It
accepts a supplied registration-observation clock for deterministic tests and
assesses whether it strictly precedes the first declared window. Its clock is
explicitly DECLARED_UNVERIFIED; this pure function does not register anything.
Keep late declarations as NOT_PROSPECTIVE rather than inventing earlier clocks.
The exact declaration and definition hashes remain reproducible; canonical symbol
ordering prevents caller ordering from changing protocol identity.

## Actual registration storage, subsequent unit

The later CLI reads a bounded local declaration, validates it, exclusively saves
its full payload, and only after fsync/close reads the actual registration clock.
A separate receipt binds the payload bytes and that observation, using the same
partial-pair and independent-recovery guarantees as context capture. It accepts
no supplied historical registration clock. A declaration whose first window has
already started can be retained as a late registration, but it never becomes a
prospective protocol. Actual receipt evidence must be verified before a decision
consumer may distinguish it from the pure declared-clock assessment.

Changing any definition, windows or strategy creates a new protocol ID; old
registrations remain intact and visible. Registration does not seal future data
or prove that an operator has not inspected outcomes through other paths.

## Subsequent decision binding, separately bounded

Require an independently recovered protocol receipt and context capture pair.
Preserve their payload/receipt, declaration, feature/outcome definition, context
and member hashes. Use the actual local decision-record clock, not a caller's
historical plan time. Both complete prerequisite receipts must precede that
clock; the context cutoff alone is insufficient. Preserve missing/blocked sources,
source freshness/coverage and the independent protocol window assessment.

Decision records describe research observations or explicit no-trade reasons;
they do not submit orders or change the old paper engine. Feature-window start,
complete feature availability, episode review, outcome knowledge and other sample
facts stay unknown until independently supported. This module cannot populate
them from context-member counts. Outcome recording and prospective paper-plan
integration need their own bounded specifications and evidence.

## Acceptance and limits

Validate exact shapes, GLD/IBIT scope, full definition text/hashes, original window
boundaries and gap limits, equal/late registration clocks, deterministic ordering,
immutable inputs/output and original zero-sample blockers. Storage acceptance adds
exclusive/partial pairs, actual post-write clocks, changed payloads, invalid JSON,
unsafe paths, preserved source files and fresh-process isolated recovery.

No probability, model fit, return target, order, market refresh, account call,
strategy-size authority, paid source, schedule mutation or automatic old-journal
rewrite. Local hashes and wall clocks remain consistency evidence without external
timestamp attestation. First qualified real-price paper execution still depends
on independently qualified quote evidence; this protocol does not unlock it.
