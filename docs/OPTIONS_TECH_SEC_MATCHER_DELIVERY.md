# Saved SEC attachment and fiscal-period matching — October 10, 2026

The existing research CLI now locates attachment candidates through actual links in saved SEC primary documents and makes issuer/period mismatches inspectable. It uses the existing source loader, receipt context and original-body extractor. This is an explicit, offline read operation with no new scanner, source request, scoring, schedule or review write.

```powershell
npm run options:tech-candidate -- --match-sec --source-root <saved-scan-directory> --request <request.json>
```

The request has exactly `version: TECH36_SEC_MATCH_REQUEST_V1`, `symbol`, `eventId`, `accession` and `savedReceipts`. The event/company must exist in the saved scan; its title is an unverified query, not body evidence. The accession must occur in that company's saved SEC submissions metadata. The matcher locates an already saved receipt matching the actual primary-document name and SEC archive identity. It never constructs or fetches a missing primary URL.

`savedReceipts` can be empty when materials are already in the scan. Otherwise it contains at most six local envelopes, each with exactly `rawPath`, `sha256`, `url`, `startedAt`, `receivedAt`, nullable `publishedAt`, `status` (`SUCCESS`, `FAILED`, `BLOCKED`) and integer `httpStatus`. Paths are confined to the request directory; the existing reader rejects symlinks/hardlinks, and each added body is limited to 2 MiB. Byte hashes and clocks are checked before matching. HTTP failures, including saved 403s, never become body evidence or trigger retries.

Only saved visible, quoted anchors to HTML files in the same SEC issuer/accession archive are attachment candidates. Relative links are resolved against the actual primary receipt URL; no attachment filename is guessed. Hidden/script/comment links and outside-scope URLs are not followed. Repeated links and identical body receipts retain their positions/clocks without multiplying a candidate; changed bodies remain distinct candidates. Output is bounded to 200 anchors per primary body and 20 candidate versions, with a limit reason preventing a unique match. No redirect or network operation is performed.

## Match semantics and trace

The October 10 P2 correction supersedes the original parser's broader issuer/period claims. Four retained synthetic counterexamples showed false `MATCH` results for a customer of another announcing company, a standalone annual heading, two query period-end dates, and a disclosure calendar date years after receipt. Those three P2 categories passed follow-up review at `a86ce59`, but that review found a further quotation-scope defect. Neither version is accepted as a general matcher. The quotation correction uses `parsePolicy: RESTRICTED_ISSUER_PERIOD_DATE_QUOTATION_V3` and awaits independent review.

`MATCH` now means one saved candidate satisfies the restricted syntax and explicit constraints below. It is not headline verification, issuer authentication, a directional plan, a probability or trading permission. Multiple candidates remain available without choosing one. Detected issuer or result-period conflicts block a unique match. Missing receipts/bodies produce `MISSING`; unsupported formats, incomplete labels and recognized ambiguity retain `UNKNOWN`. Finite pattern recognition cannot guarantee detection of every conflicting natural-language statement.

Attachment subject binding requires an entire extracted block to match the saved legal name followed immediately by `(NYSE: SYMBOL)` or `(NASDAQ: SYMBOL)`, optional `today`, `announced` or `reported`, optional `financial`, then `results for its/the first/second/third/fourth quarter`, an optional supported year label, and `ended Month DD, YYYY`. An optional uppercase-city/date dateline and final period are supported. Case and punctuation are intentionally narrow. Customer/partner relations, quotations, joint announcements, passive or reported speech, descriptive appositives and other unsupported announcement blocks cannot establish this binding; they remain `UNKNOWN`, even if a separate valid issuer sentence exists. Explicit identifier contradictions remain `CONFLICT`. Primary-document CIK/registrant checks are retained. An archive path, name, hash or ticker is not machine authentication.

Quotation scope is checked before that restricted subject grammar. A strict lexical tag stack tracks case-insensitive `q` and `blockquote` elements, including mixed nesting and an outer quote that remains open after an inner quote closes. An announcement block overlapping those source ranges cannot establish an issuer subject. A correctly closed neutral quote before a separate ordinary announcement block does not contaminate that later block. Comments and raw-text contents are not interpreted as nested tags; raw-text element ranges cannot establish announcement subjects either. Source offsets refer to the original decoded UTF-8 characters. The output exposes the inspected ranges and any refusal reason.

This is a conservative saved-markup subset, not browser HTML parsing or error recovery. It accepts explicitly balanced ordinary tags, common void tags and simple quoted/unquoted attributes. Mismatched or missing closes, non-void self-closing tags, unterminated comments/tags/attributes, angle brackets inside attribute values, unsupported declarations, and unsupported content models such as SVG, MathML, templates and noscript make quotation scope unknown and block issuer `MATCH`. Legitimate HTML using omitted end tags or other unsupported syntax can therefore remain `UNKNOWN`. No new parser dependency, module, script execution or network access is introduced.

The parser preserves all recognized quarter and `ended/ending Month DD, YYYY` occurrences, annual/full-year markers, and results/guidance roles across the query, primary document and all extracted attachment blocks. It does not select the first distinct period end. Standalone annual headings and unscoped period mentions block a match. Distinct current-result claims conflict; repeated identical dates remain visible. Explicit prior-period comparison suffixes and table cells are retained separately and do not become current-result claims, so a normal historical comparison table alone does not reject an otherwise supported release. Unsupported prose comparison layouts may still require review. Guidance sections retain their separate role; mixed results/guidance requires review. Fiscal year is never inferred from calendar year. The matcher reports claims and original UTF-8 character coordinates/block indices rather than numerical operating facts.

Each result carries scan/policy and request hashes, implementation hashes, source envelopes, actual main-link coordinates and cited body blocks. Recognized announcement datelines and labelled disclosure dates retain date-only precision and unknown timezone. Calendar-date possibilities over UTC-12 through UTC+14 are compared with both actual receipt and as-of clocks: a definitely later date conflicts, overlapping possibilities remain unknown. These bounds are not publication timestamps; no midnight publication instant is generated. SEC acceptance, metadata report date, discovery publication/receipt and body retrieval clocks remain separate. A saved acceptance time later than its metadata receipt is rejected.

Guidance revision remains unknown without an explicitly reviewed comparable previous/current pair for the same target period, metric, basis, currency, unit and scope. No operating-number or guidance-delta extraction is added. Consensus surprise remains unknown without independent comparable evidence captured before announcement.

The result exposes body citation references usable by the unchanged [explicit event-review append contract](specifications/OPTIONS_TECH_EVENT_REVIEW_V1.md). It does not construct verification flags or append a review. The separate synthetic handoff test shows that even a `MATCH` leaves pending coverage unchanged until an explicit review is submitted, and an incomplete explicit review still remains pending.
